The idea

AI agents will draft, negotiate and track work for people. PaySettle lets an agent do that work through its own MCP server, within a spend limit its person sets, while a person approves every hold and every release. The agent can ask; it cannot pay.

Agent tokens and spend limits

A person mints an agent token on AI & agents (/account/ai), with a label and a spend limit. The token acts only as that person, only within the limit, and can be revoked there.

Walkthrough: playground scenario S6

Sign in as Hackathon Judge, open the Judge Playground, choose Fast mock and start S6 Agentic — Consulting sprint over MCP. Press Run next step to go one at a time:

  1. Mint agent tokens for both parties: the client's agent and the provider's agent each get a scoped token.
  2. Agent: draft_contract: the client's agent drafts a consulting sprint from a vetted blueprint.
  3. Provider agent: propose_changes: the provider's agent proposes edits.
  4. People review and sign: both people sign the same revision and hash. Agents cannot sign.
  5. Agent: request_funding: the client's agent creates the PayPal order within its spend limit.
  6. Person approves the hold: the client approves in PayPal; only now is the money held.
  7. Provider agent: submit_evidence: the provider's agent submits the proof.
  8. Agent: approve_release: the client's agent asks for the release; a pending request is recorded and no money moves.
  9. Person approves with MFA → release: the client confirms with an authenticator code, and PayPal captures that milestone.

The Wire log view shows each MCP call next to the PayPal calls it led to.

How it is tested

Cheat attempts C08 (an agent calls approve_release) and C09 (an agent goes past its spend limit) run on every push; see Can it be cheated?. A static test fails the build if any AI code can reach code that moves money. More: blog post "Letting an AI agent buy a service safely" on the live site.
