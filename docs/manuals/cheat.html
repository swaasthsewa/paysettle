Why the AI is never the judge

If an AI's verdict releases the money, whoever fools the AI is paid. In PaySettle the AI only advises, so fooling it gets you wrong advice and nothing else. Money reaches PayPal only through a signed decision: the client's approval with an authenticator code over the evidence fingerprint, sealed offers from both sides that meet, or a human mediator's signed verdict (co-signed by a second mediator above $5,000).

The AI boundary

A static test (src/lib/ai/boundary.test.ts) follows every import from the AI code and fails the build if any of it can reach code that moves money or writes a contract, ledger row, signature, release or verdict. The MCP bindings may hand agents only entry points that a person still gates.

Where it can still be fooled

  • A well-forged photo can fool the client as well as the AI. The mediator and the evidence vault are the backstop; reading signed camera photos (C2PA) and independent inspections for physical work are next.
  • In the sandbox demo, a client without an authenticator can approve without a code; outside the sandbox the code is required.
  • Sealed offers are hidden from the other party, not encrypted in the database.
  • Someone with write access to the database could move money between the milestones of a locked contract (same total): the contract's fingerprint shows the change, but it is not yet re-checked before funding or release, because a rollover moves milestones between tranches without a new revision.
  • Someone with full database administrator rights can switch off triggers, as on any database; the hash-linked audit log shows a naive edit.
